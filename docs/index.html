Design System · v0.1

Fernwell UI System

Warm, rounded, and legible — built to feel approachable to a first-time consumer trial and sturdy enough for the team running their business through it every day.

npm ↗

Install

00

One package, three ways to add to your project. Fonts are not bundled — add the Google Fonts link (or self-host) and the tokens' fallback stacks cover the rest.

Script tag / CDN

No build step. Exposes window.Fernwell and auto-initialises on DOMContentLoaded — add data-fw-no-init to the script tag to wire things up yourself.

<link rel="stylesheet" href="https://unpkg.com/fernwell/dist/fernwell.min.css">
<script src="https://unpkg.com/fernwell/dist/fernwell.iife.js"></script>

npm + bundler

ESM and CommonJS builds with types. init() wires every data-fw-* hook on the page and is safe to call again after injecting markup.

npm install fernwell
import 'fernwell/css';
import { init, toast } from 'fernwell';

init();
toast.show('Invoice sent');

CSS only

Everything is plain CSS and custom properties — no JavaScript required. Import just the tokens if you only want the palette and scales.

@import 'fernwell/css';          /* tokens + base + components */
@import 'fernwell/tokens.css';   /* just the custom properties */

Color

01

Tokens are named by role, not by hex — Primary carries the energy and is used sparingly, only for the action you most want taken; Secondary grounds the interface and does the heavy lifting in navigation and headers; Text and Background do 90% of the actual work on any given screen. Fernwell's default palette (Marigold, Plum, Meadow…) is just the starting value for each role — retheme any of them, see Theming below.

Dark theme
Not a straight inversion. Primary stays the same hex in both themes by default. Neutrals move from warm cream to near-black (never pure black), status colors lift 1–2 steps lighter, and tinted backgrounds become low-opacity washes.
on-primary
Anything sitting on Primary (buttons, avatars) uses --fw-on-primary for text, so it never fights the theme toggle — or a retheme.
Seeds vs. derived
The eight swatches above (plus Surface and a few translucent neutrals) are seeds — override these. Hovers, tints, the focus ring, and CTA glows are derived from them with color-mix() and follow automatically.

Theming

01b

Every seed token can be overridden — in a stylesheet or at runtime — and every derived token (hovers, tints, the focus ring, CTA glows) follows automatically, in both themes. Try it:

:root { }
CSS — static
Redeclare any seed after the stylesheet — it wins over both themes, no need to repeat it for [data-theme="dark"]: :root { --fw-primary: #2266ff; }. Set [data-theme="dark"] { --fw-primary: #5c9dff; } too if you want a different value in dark.
JS — runtime
Fernwell.theme.setTokens({ primary: '#2266ff' }) — same effect, applied on the fly. Pass { light: {…}, dark: {…} } to split by theme, and { scope: '.tenant-acme' } to theme one subtree instead of the whole page. Fernwell.theme.resetTokens() clears every runtime override; Fernwell.theme.getToken('primary') reads the live, resolved value.
Scoped example
Fernwell.theme.setTokens({ primary: '#a33' }, { scope: '.tenant-acme' }) retints just .tenant-acme — everything outside it keeps the default palette.

Buttons

04

Primary is Marigold and appears once per view. Secondary (Plum) is for the next-most-important action. Ghost for anything tertiary. Only one Primary button visible at a time — if two things feel equally important, neither is Primary.

Progress & loading

04b

Determinate bars for anything with a known length. Indeterminate bars for anything with an unknown duration. Spinners live inline — never as a full-page takeover unless the whole screen is genuinely blocked.

Motion

09
Buttons & controls
120ms ease, 1px lift on hover. Never bounce — playful lives in shape and color, not in springy easing.
Cards & modals entering
180ms, fade + 8px rise. No scale-up — it reads as cheap on data-dense screens.
Success states
A single checkmark draw-in (~300ms) is the one place a slightly more expressive animation is earned.
Reduced motion
All transforms drop to opacity-only fades when prefers-reduced-motion is set.

Voice

10
Buttons
Name the action, not the mechanism: "Send invoice," not "Submit."
Errors
Say what happened and what to do next. Never apologize, never blame the user: "That card was declined," not "Oops! Something went wrong."
Empty states
An invitation, not a description: "No invoices sent yet" + a direct next action, not "You have no data."
Confirmations
Match the verb on the button: "Send invoice" → "Invoice sent."

Icons

11
Style
Outline only, 16–20px box, 1.3–1.4px stroke, round caps and joins, currentColor.
The one exception
No fills, except a checkmark on a completed item — the one place a filled icon carries meaning instead of decoration.
