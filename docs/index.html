Design System · v0.1

Fernwell UI System

Warm, rounded, and legible — built to feel approachable to a first-time consumer trial and sturdy enough for the team running their business through it every day.

Install

00

One package, three ways in. Fonts are not bundled — add the Google Fonts link (or self-host) and the tokens' fallback stacks cover the rest.

<!-- 1. CDN, no build step -->
<link rel="stylesheet" href="https://unpkg.com/fernwell/dist/fernwell.min.css">
<script src="https://unpkg.com/fernwell/dist/fernwell.iife.js"></script>   <!-- window.Fernwell, auto-inits -->

<!-- 2. npm + bundler -->
npm install fernwell
import 'fernwell/css';
import { init, toast } from 'fernwell';
init();

<!-- 3. CSS only -->
@import 'fernwell/css';            /* or fernwell/tokens.css for just the variables */

Color

01

Marigold carries the energy — used sparingly, only for the action you most want taken. Plum grounds the interface and does the heavy lifting in navigation and headers. Ink and Cloud are doing 90% of the actual work on any given screen.

Dark theme
Not a straight inversion. Marigold stays the same hex in both themes. Neutrals move from warm cream to near-black (never pure black), status colors lift 1–2 steps lighter, and tinted backgrounds become low-opacity washes.
Ink-Fixed
Anything sitting on Marigold (buttons, avatars) uses --fw-ink-fixed for text, so it never fights the theme toggle.
Overriding
Redeclare any token after the stylesheet: :root { --fw-marigold: #f0b030; }. Every component reads tokens, none hardcode values.

Shape

03

One rounding system, four scales. The bigger the surface, the softer the corner — this is the single rule that ties every component together.

Buttons

04

Primary is Marigold and appears once per view. Secondary (Plum) is for the next-most-important action. Ghost for anything tertiary. Only one Primary button visible at a time — if two things feel equally important, neither is Primary.

Progress & loading

04b

Determinate bars for anything with a known length. Indeterminate bars for anything with an unknown duration. Spinners live inline — never as a full-page takeover unless the whole screen is genuinely blocked.

Form fields

05

A required field gets a small coral asterisk after the label, always shipped with hidden text for screen readers. Disabled fields mute to the Cloud-dim surface and drop the border contrast, signalling "not available" rather than "empty."

Motion

09
Buttons & controls
120ms ease, 1px lift on hover. Never bounce — playful lives in shape and color, not in springy easing.
Cards & modals entering
180ms, fade + 8px rise. No scale-up — it reads as cheap on data-dense screens.
Success states
A single checkmark draw-in (~300ms) is the one place a slightly more expressive animation is earned.
Reduced motion
All transforms drop to opacity-only fades when prefers-reduced-motion is set.

Voice

10
Buttons
Name the action, not the mechanism: "Send invoice," not "Submit."
Errors
Say what happened and what to do next. Never apologize, never blame the user: "That card was declined," not "Oops! Something went wrong."
Empty states
An invitation, not a description: "No invoices sent yet" + a direct next action, not "You have no data."
Confirmations
Match the verb on the button: "Send invoice" → "Invoice sent."

Icons

11
Style
Outline only, 16–20px box, 1.3–1.4px stroke, round caps and joins, currentColor.
The one exception
No fills, except a checkmark on a completed item — the one place a filled icon carries meaning instead of decoration.
