API Usage

Install Fernwell, wire up its enhancers, and build your own components from the same tokens, classes and JavaScript API the built-in ones use.

Component reference

Install

00

One package: design tokens, CSS components and a few small vanilla-JS enhancers. Pick whichever way of loading it fits your project — they all ship the same classes and the same API.

Script tag / CDN

No build step. Exposes window.Fernwell and runs Fernwell.init() on DOMContentLoaded. Fernwell is 0.x, so minors can break — pin the version in production.

<link rel="stylesheet" href="https://unpkg.com/fernwell@latest/dist/fernwell.min.css">
<script src="https://unpkg.com/fernwell@latest/dist/fernwell.iife.js"></script>

npm + bundler

ESM and CommonJS builds with TypeScript types. Nothing runs until you call init().

npm install fernwell
import 'fernwell/css';               // or 'fernwell/css/min'
import { init, toast } from 'fernwell';

init();                              // wires every data-fw-* hook on the page
toast.show('Invoice sent');

CSS only

Every component is plain CSS and custom properties; the JavaScript only adds behaviour. Import just the tokens if you only want the palette and scales.

@import 'fernwell/css';          /* tokens + base + every component */
@import 'fernwell/tokens.css';   /* just the custom properties */

Fonts

Fonts aren't bundled. Add the three faces from Google Fonts (or self-host them) — each font token carries a system fallback stack either way.

<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=Plus+Jakarta+Sans:wght@500;600;700;800&family=Inter:wght@400;500;600;700&family=IBM+Plex+Mono:wght@500;600&display=swap" rel="stylesheet">

Page setup

Both optional. The inline script applies the saved or OS theme before first paint. fw-root opts the page into Fernwell's defaults; its resets use :where(), so any rule of yours wins.

<!-- in <head>, before the stylesheet: no flash of the wrong theme -->
<script>document.documentElement.dataset.theme=localStorage.getItem('fw-theme')||(matchMedia('(prefers-color-scheme: dark)').matches?'dark':'light')</script>

<!-- optional page defaults: Background, Text, Inter body, display headings -->
<body class="fw-root">

Initialise

01

Everything interactive is progressive enhancement over plain HTML: mark it up with data-fw-* attributes and init() binds the behaviour. It only binds elements it hasn't seen, so it's safe to call as often as you like.

// HTMX, Turbo, or a plain fetch-and-insert:
const panel = document.querySelector('#client-panel');
panel.innerHTML = await (await fetch('/clients/42')).text();

Fernwell.init(panel);   // only the new elements get bound
<script src="https://unpkg.com/fernwell@latest/dist/fernwell.iife.js" data-fw-no-init></script>
<script>
  document.addEventListener('DOMContentLoaded', () => {
    Fernwell.theme.set('light', { persist: false });  // your own setup first…
    Fernwell.init();                                   // …then wire the hooks
  });
</script>
import { useEffect, useRef } from 'react';
import { init } from 'fernwell';

// Wrap any subtree that uses data-fw-* hooks.
export function Fernwelled({ children }) {
  const ref = useRef(null);
  useEffect(() => { init(ref.current); }, []);
  return <div ref={ref}>{children}</div>;
}
init(root?)
Runs every module's initialiser under root. Scope it to the element you just inserted rather than re-scanning the whole document.
Per-module init
Only need one enhancer? Each module has its own — tabs.init(el), menu.init(el), icon.init(el) — so a bundler can drop the rest.
data-fw-no-init
On the CDN script tag, skips the automatic DOMContentLoaded call so you can run setup first.

Build your own components

02

Fernwell is meant to be extended, not forked. A custom component that follows the rules below inherits dark mode, retheming and the system's shape and motion for free — and keeps working when you upgrade.

Use your own prefix
Name classes and hooks acme-* / data-acme-*. The fw- namespace belongs to the package, and any rename there is a semver change you'd collide with.
Compose first
Start from .fw-card, .fw-btn, .fw-tag, .fw-icon… and add only what's missing. Never restyle an fw- class globally.
Tokens, never values
Every colour, space, radius, font, shadow and duration is a --fw-* property. A raw hex is the one thing that won't follow dark mode or a retheme.
Seeds, not derived
Read any token, but only override seeds (--fw-primary, not --fw-primary-hover).
Shape by size
Inputs --fw-r-sm, buttons -md, cards -lg, modals -xl. Borders are always --fw-border-w.
State is visible
Use is-* classes and ARIA attributes for state, and emit bubbling acme:* events the way Fernwell emits fw:*.

// acme-copy.js — a custom enhancer written the same way Fernwell's own are.
import { init, icon, toast } from 'fernwell';

export function initCopy(root = document) {
  root.querySelectorAll('[data-acme-copy]').forEach((el) => {
    if (el.dataset.acmeBound) return;         // idempotent, like Fernwell's init()
    el.dataset.acmeBound = '1';

    const input = el.querySelector('input');
    const button = el.querySelector('[data-acme-copy-button]');
    const glyph = button.querySelector('.fw-icon');

    button.addEventListener('click', async () => {
      try {
        await navigator.clipboard.writeText(input.value);
      } catch {
        input.select();
        toast.show("Couldn't reach the clipboard. The link is selected — press Ctrl+C.", { variant: 'error' });
        return;
      }
      el.classList.add('is-copied');           // state as an is-* class
      glyph.innerHTML = icon.render('check');  // swap to a built-in icon
      toast.show('Link copied');               // voice: echo the action
      el.dispatchEvent(new CustomEvent('acme:copy', { bubbles: true, detail: { value: input.value } }));

      setTimeout(() => {
        el.classList.remove('is-copied');
        glyph.innerHTML = icon.render('copy');
      }, 1500);
    });
  });
}

import { useEffect, useRef, useState } from 'react';
import { init, icon, toast } from 'fernwell';

export function CopyField({ value, label }) {
  const ref = useRef(null);
  const [copied, setCopied] = useState(false);

  // Let Fernwell wire the icon + tooltip inside this subtree.
  useEffect(() => { init(ref.current); }, []);

  async function copy() {
    try {
      await navigator.clipboard.writeText(value);
      setCopied(true);
      toast.show('Link copied');
      setTimeout(() => setCopied(false), 1500);
    } catch {
      toast.show("Couldn't reach the clipboard. Select the link and press Ctrl+C.", { variant: 'error' });
    }
  }

  return (
    <div ref={ref} className={`acme-copy${copied ? ' is-copied' : ''}`}>
      <input className="acme-copy-value" type="text" readOnly value={value} aria-label={label} />
      <button type="button" className="fw-icon-btn" onClick={copy}
              aria-label="Copy link" title="Copy link" data-fw-tooltip>
        <span className="fw-icon" dangerouslySetInnerHTML={{ __html: icon.render(copied ? 'check' : 'copy') }} />
      </button>
    </div>
  );
}

Render

Theme it

Because the components above only read tokens, retheming them is one declaration. Override seeds statically in CSS, or at runtime with tokens.setTokens() — optionally scoped to one subtree. Try it on the copy-field demo:

/* Whole app: redeclare a seed after Fernwell's CSS.
   Hovers, tints and the focus ring follow in both themes. */
:root {
  --fw-primary: #2f7de1;
  --fw-secondary: #1e6b5c;
}

/* Only where you want a different dark value: */
[data-theme="dark"] {
  --fw-secondary: #3fa58f;
}
import { tokens } from 'fernwell';

// Runtime, one subtree — e.g. a tenant's brand or a live preview.
tokens.setTokens(
  { primary: '#2f7de1', secondary: '#1e6b5c' },
  { scope: '#custom-demo' }
);

tokens.getToken('primary');        // → the live, resolved value
tokens.resetTokens('#custom-demo'); // clear just that scope

Declarative hooks

04

The markup-only side of the API: what init() looks for. Anything you can do with a hook you can also do from JavaScript with the module above.

Fernwell data attributes

[data-fw-theme-toggle]Flips data-theme, persists it, sets aria-pressed. Label and icon swap per theme via data-fw-theme-label-light / -dark and data-fw-theme-icon-light / -dark.

[data-fw-theme-scope='{…}']Themes just this element's subtree from a JSON object of tokens. Never persisted; undone on the next init() after the element is removed.
[data-fw-icon="name"]Renders a built-in outline icon, sized in em, coloured by currentColor.
[data-fw-open-modal="id"]

Before you ship a component

06
  • It looks right in both themes with no [data-theme="dark"] rule of its own.
  • Changing --fw-primary in the Theming editor on the Overview page retints it.
  • It's fully usable by keyboard, focus shows --fw-focus-ring, and icon-only buttons have an aria-label.
  • Transitions use --fw-motion-fast / -base and drop to none under prefers-reduced-motion.
  • Its enhancer can run twice on the same element without double-binding.
  • Copy follows the Voice rules: buttons name the action, errors say what to do next.

Fernwell v — the example components on this page live in styles/api.css and use nothing but public --fw-* tokens, fw- classes and the exported API. That's the whole contract.
